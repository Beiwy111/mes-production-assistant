# 同步到 2026-11-27 的助手版本

## 队友更新已有项目

在自己的仓库目录执行以下命令。若有未提交改动，先提交到自己的分支；不要用 reset --hard 覆盖。

```powershell
git switch main
git pull --ff-only origin main
.\Initialize-Assistant.cmd
```

初始化器会复用本机配置，核对公开知识索引，并把最新工作流模板发布到本机 Dify。它不是只复制代码：七个 Agent 的应用 ID、角色凭据和工具绑定必须属于队友自己的 Dify 工作区。运行时使用旧代码时，先正常停止原来的助手进程再启动，勿在另一份 checkout 同时启动相同端口。

按原来的方式重新启动 MES 后端；前端更新依赖后启动：

```powershell
# 后端终端
cd backend
mvn spring-boot:run

# 另一个终端，从仓库根目录开始
cd frontend
npm ci
npm run dev
```

全新电脑所需环境、数据库准备和首次输入项目见 [NEW-COMPUTER.md](NEW-COMPUTER.md)。需要队友自己的 DeepSeek、DashScope Key，本机 MySQL/Redis 和 Dify 管理账号。已有本机 Key 不应从别人的配置文件覆盖。

## 本次同步的功能

- 自然语言质量分析、统计口径、上下文和物料/成品库存区分。
- 生产计划与派工分离，多订单生产计划、真实计算阶段、确认后执行。
- 派工预览中选择操作员；重新校验和重新确认后下发，保留原操作员任务收件流程。
- 中间对话区和右侧共享真实协作事件，保留流式输出。
- 知识工作台显示当前授权范围内全部节点，PDF 入库时显示真实解析、切片、向量和图谱阶段。
- 保留 GitHub 原有的人脸登录、API/本地模型切换和新电脑初始化功能。

生产计划、派工和 Agent 协作请选择「业务工作流」。API/本地模型入口沿用已有能力，不能绕过业务操作确认或权限检查。

## RAG / GraphRAG 如何同步

仓库包含 7 篇 CC BY 4.0 论文 PDF、分页原文、来源及 SHA-256 清单、11 份实践参考资料、经过整理的关系声明、固定模型版本及索引程序。PDF 在 `docs/ai-planning-2026-11-07/papers/P01.pdf` 至 `P07.pdf`。署名、来源和许可见 `backend/assistant/rag/corpus/papers.json`；实践参考的来源保存在 `corpus/practice`。

初始化会在队友自己的电脑准备 multilingual-e5-small，清洗/切片/嵌入并写入 Qdrant，再建立 Neo4j 关系。Git 不包含 Docker 卷、运行中的数据库、API Key、人脸样本、个人会话或管理员私有上传库。

本版公开库基线是 **18 个文档、290 个片段、335 个混合图可视化节点**。335 包括文档、片段、实体和关系节点，不能与 Neo4j 物理节点数或 GraphRAG 单模式数量直接比较。管理员个人上传的资料不属于这 18 份公开文档，因此队友初始节点数不一定等于开发机「全部可访问资料」总数。

若要演示 PDF 入库：用自己的管理员账号打开「联合知识图 → 资料入库」，选择 `P01.pdf` 或其他有权使用的 PDF；观察解析 → 切片 → 向量化 → Qdrant → 实体/关系 → Neo4j，完成后选择「查看本次新增图谱」。P01 已在公开库，重新上传只是独立上传流程演示，不代表新原创知识。入库资料中的候选关系不能作为已确认根因。

```powershell
& .\backend\assistant\rag\.venv\Scripts\python.exe .\backend\assistant\deploy\Verify-NewComputer.py
& .\backend\assistant\rag\.venv\Scripts\python.exe .\backend\assistant\deploy\Verify-NewComputer.py --live
```

确认公开图谱底部「已展示 X / X」完整；询问 Mura 检测方法应带文档/页码；日常问答不应强制业务 Agent；为自己库里的已审核订单制定生产计划，先看到库存、物料和交期计算，再确认保存，随后提出派工请求。没有确认时不得写入生产任务。

业务订单、库存、人员负荷取队友本机数据库，不会随 git pull 自动变成开发机的数据。私有资料如需共享，必须单独选择有权共享的原件并在目标机重新上传，不能把整个个人上传数据库当公开资料提交。

## 开发测试

前端 `src` 下的 Node 测试可通过 PowerShell 执行 `node --test @(rg --files src -g '*.test.js' -g '*.test.mjs')`；后端离线测试为 `mvn test`。RAG 和 Dify 测试在根目录运行：设置 `PYTHONPATH=backend/assistant/rag/src`，用专用 Python 环境执行 `-m pytest backend/assistant/rag/tests backend/assistant/agents/tests -q`。

需要实际 MES Spring 上下文和业务库的三项历史集成测试默认不运行。准备本机 JWT、MySQL、Redis 与其他必需配置后，设置环境变量 `MES_LIVE_INTEGRATION=1` 并执行 `mvn "-Dtest=ComputerApplicationTests,AssistantFactoryContextIntegrationTest,AssistantInventoryFallbackIntegrationTest" test`。其他实机测试继续使用各自的 opt-in 开关。不要为通过离线测试在仓库中加入真实密钥，也不要把跳过的实机测试报告为已通过。

本次发布目录验证：Java 650 项（633 通过、17 条件跳过，失败/错误为 0）；前端 Node 275 项通过；RAG/Dify Python 193 项通过、2 项跳过；前端构建通过；知识工作台和 PDF 入库两组带接口夹具的浏览器回归通过。7 篇 PDF 及分页文本通过清单哈希校验，知识源内容与开发目录一致。此结果不代表已在队友电脑调用其供应商 Key 或验证其业务库，目标机仍须执行上述初始化和 live 验收。
