# 对话内实时 Agent 协作流

本轮保留白色主题、头像、现有查询/Dify/RAG/GraphRAG、图片与业务确认功能。

## 实现

- 中间 `AgentCollaborationStream.vue` 和右侧 `AgentInspector.vue` 都使用 `inspectAgentMessage` 投影同一个消息事件仓库，无额外查询或轮询。
- 生产办理不再被中间协作组件排除，协作记录在最终回答和确认卡片之前。实际任务展开，结束自动折叠，可手动重开。
- 工具开始/完成按调用 ID 合并，同一 Agent 的不同轮次、并行工具和重试分别保留。交接来自实际 HANDOFF。没有执行事件的角色不显示成已调用。
- `collaborationTimeline.js` 只投影已规范化的记录；失效证据隐藏，取消不会推断完成。保留旧会话已记录的摘要，不编造缺少的工具明细。
- 动画只用于新节点出现、现有头像和执行状态，不推迟请求、队列消费或真实完成事件。支持系统减少动态效果偏好。
- 普通问答沿用真实模型分流，直接回答，不创建业务协作记录。

## 后端时序

`EverydayChat.planTask` 使用原生函数选择，额外的 `respond` 是结束本轮规划的控制信号，不是业务工具、角色或写入动作。它不能与待执行工具混用。

规划阶段不输出公开正文，避免工具选择前的模型描述混入最终回答。规划器选择 respond 后，才以已有查询结果和任务状态开始独立的最终回答请求，正文仍是原生模型增量，不把完整回答拆字冒充流式。此方式增加一次真实回答模型请求，换取工具执行与回答阶段的明确分离。

主后端在回答首段之前推送真实汇总阶段，工具结果、规划步骤、交接和回答使用原 SSE 协议。业务预览表单及确认说明仍是确定性业务结果，不人为拆分成模型增量。

原查询入口已只允许 Dify 的 response_llm 最终节点输出正文，保留其权威结果校验，不修改 Dify 工作流或凭据。
