# 人脸隐私、活体与许可边界

## 活体评估结论

当前 CompreFace 1.2.0 的公开服务/插件包括检测、识别、验证、关键点、头部姿态等，本集成未接入经验证的呈现攻击检测（PAD）能力。单张清晰人脸、头部姿态和随机请求凭证均不能证明活体，不能据此宣称能抵抗打印照片、屏幕回放、预录视频或虚拟摄像头注入。

自动检测版本连续处理摄像头帧，仅以两帧的图像质量和人脸框位置稳定性选择提交时机，不推断两帧属于同一人，也不是活体检测。最终登录仍对指定账号的样本进行 1:1 验证。

本版本固定返回 `livenessAvailable=false` 和 `demoOnly=true`，登录界面明确提示；只有显式设置 `FACE_AUTH_ALLOW_DEMO_LOGIN=true` 才开放演示登录。保留密码登录，录入/更新/删除要求当前账号密码。正式生产不得把这一人脸功能作为唯一认证因素。以后如引入成熟 PAD，应另行检查模型许可、传感器要求、重放/注入对抗和误接受/误拒绝数据；本次没有训练或宣称验证任何 PAD 模型。

官方能力列表：https://github.com/exadel-inc/CompreFace/blob/v1.2.0/docs/Face-services-and-plugins.md

## 数据处理与删除

采集目的为当前 MES 的人脸绑定和账号验证。用户阅读当前版本说明并主动同意后才开启采集；服务端检查授权版本。已登录用户只能录入本人账号，管理操作要求重新验证密码；管理员仅查看状态和撤销绑定。摄像头关闭、弹窗关闭或取消授权会停止媒体流并清除页面中的采集状态。

连续采集要求用户主动点击开始，授权版本为 `face-demo-2026-11-v3`。最多 30 帧/60 秒，不在后台页面持续采集；取消会中止浏览器请求并忽略迟到的响应，但已经发往后端/CompreFace 的单帧可能仍完成内存处理。匿名预检测只返回当前图像的质量提示和人脸框，使用独立来源限流及进程并发上限；它不建立绑定、不检索业务账号、不创建会话。完成采集、失败或请求异常均会停止该轮检测，用户需主动开始下一轮。

录入/更新在自动采集后暂停，展示实际照片和目标账号，需本人确认后才修改绑定。已有绑定默认进入匹配测试，避免将测试另一位参与者误当作更新。待确认照片和匹配测试的实际送检画面只保存在当前页面内存；取消、撤销授权、切换模式或关闭弹窗时清除，不写浏览器持久化存储。界面确认不能替代账号身份核验；掌握当前密码和会话的人仍可授权修改账号绑定，应避免共享业务账号进行不同人员的录入。

MES 不保存原图和向量，仅有绑定元数据、授权时间和操作审计；请求使用有大小上限的内存 JSON，图像重编码剥离元数据，避免 multipart 临时落盘。密码/图片 DTO 的 toString 已脱敏，专用异常处理不输出敏感请求和原始上游错误。真实图像不用于自动化测试，也不加入版本库。

课程排错用“匹配测试”要求当前有效会话、本人账号密码和当前参与者授权，只比较当前账号的绑定；不会录入他人、不产生新登录会话。分数和阈值只在这个已认证接口中返回，匿名登录失败不返回详细分数。比对分数、阈值和绑定版本写入受限审计表，用于定位错人放行；不记录照片、向量或上游正文。

CompreFace 自身默认保存原图。独立 Compose override 将新请求的 `SAVE_IMAGES_TO_DB=false`，特征仍由它的 PostgreSQL 持久化，匹配由 CompreFace 完成。这不意味着已经删除历史照片。镜像/模型升级迁移可能需要重新录入，按官方迁移要求评估。

删除确认分为：本地绑定已撤销、远端 API 确认已删除、远端待清理。对方不可用时仅报告本地撤销和待清理，不能伪报完全删除。远端 API 成功也不证明 PostgreSQL WAL、备份、磁盘快照或既有截图已经物理擦除；部署维护者需要管理这些副本的保留与到期删除。清理待办完成后移除对应任务；保留不含人脸内容的授权/操作审计，保留期限应由系统管理者确定。

隐私配置依据：https://github.com/exadel-inc/CompreFace/blob/v1.2.0/docs/Configuration.md

绑定 Subject 包含服务地址及 Recognition Key 的不可逆摘要。更换服务配置后，原绑定不能在新服务中验证，清理任务也不会把新集合的 404 误当作旧集合已删除。恢复原地址和 Key 才能清理旧样本；密钥轮换应先按授权清理或完成显式迁移。

## 模型许可

CompreFace 仓库软件使用 Apache-2.0，不能将它自动解释为所有预训练权重及训练数据都允许任意商业用途。当前复用用户部署的官方 CPU 1.2.0，不替换或训练识别模型。实际权重及依赖以所运行镜像配置为准，商用前需逐项记录模型来源、版本和许可。

特别是 InsightFace 官方明确指出，其公开预训练模型通常限非商业研究用途，需要商用时应取得相应授权。即使使用 FaceNet，也应核对所选权重及数据集的许可，而不只看库代码许可。本次交付没有作商业许可背书。

- CompreFace 软件许可：https://github.com/exadel-inc/CompreFace/blob/v1.2.0/LICENSE
- InsightFace 模型许可：https://github.com/deepinsight/insightface#license

## 运维检查

确认 API Key 仅存在后端环境或 git 忽略的本机配置，前端源码、构建产物、浏览器请求均不得出现。保留 CompreFace 自己的管理登录，限制其端口入站访问；不要公开 PostgreSQL。启用 HTTPS 用于跨主机访问。操作系统权限、内存转储、备份管理和反向代理日志仍属于部署维护范围，不能仅靠前端隐藏解决。
